## 1. 项目定位

**一句话**：主题驱动的股票研究放大器 + 个人决策框架引擎。

不是每日信号轰炸机，而是帮我解决**“现在到底该买还是该卖”**这个核心痛点的工具。
我给方向和模糊判断，它帮我：

1. 把主题（如“中国军工”）展开成可验证的产业链图谱和标的清单。
2. 把我的入场逻辑结构化成多维打分框架（技术 / 基本面 / 情绪）。
3. 持仓后持续跟踪我进场时定的“核心故事”是否还成立。
4. 基于框架而非感觉，给出“该不该动、为什么”的结构化判断。

### 边界（硬约束，永远不破）

- 本系统是**研究和信息整理工具**。持仓数据**只读**。
- **不执行任何交易、转账操作。**
- **不给个性化买卖建议**（不是持牌投资顾问）。
- 所有打分、信号、框架评估都是**辅助判断的结构化信息**，最终决策和下单始终由我手动完成。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 语言/环境 | Python + **uv** | 轻量、现代 |
| A股/港股数据 | **akshare** | 免费、覆盖最全，全市场标的 + 产业链基础 + 北向资金 |
| 港股/美股实时+持仓 | **futu-api** | 需 FutuOpenD 网关常驻 |
| 美股/中概持仓 | **IBKR** | 只读持仓 |
| LLM | **Claude API** | 产业链展开、直觉拆解、框架评估 |
| 缓存存储 | **SQLite** | 行情/图谱/框架/历史决策 |
| 观点&日报 | **Notion** | 观点库、决策记录、日报 |
| 调度 | **launchd** (Mac) | 收盘后跑，支持休眠补跑 |

## 4. 核心设计原则

1. **LLM 不报代码，只报公司名**。所有 A股 6 位代码 / 港股 / 美股 ticker 由 `resolver.py`
   查 akshare 标的表确定。这是防幻觉的关键。
2. **代码算确定性指标，LLM 做叙事解读**。技术指标、打分、资金流由代码算好，
   LLM 只负责归因和框架评估，不做数值计算。
3. **基于“故事失效”而非“涨跌幅”判断出场**。
4. **只推偏离预期的信号**，不刷屏。

## 5. 决策框架工作流（系统灵魂）

### Day 1 — 定义框架（手动）

```
主题: 中国军工
核心故事: 国防订单前置 + 产业链景气上升

入场条件:
  技术: 龙头(航发动力)突破 200 日线 + 成交量 > 3 亿
  基本面: 上游材料库存回升(钛材/高温合金报价走强)
  情绪: 北向连续净买入 > 5 亿/日

出场条件:
  证伪: 订单预告转负 OR 北向转为净卖出
  技术: 破 20 日线 + 量能萎缩
  组合规则: 任意 2 个维度红灯即出
```

### Day N — 系统每日监控输出（示例）

```
军工主题评分: 75/100
  技术: 70 (接近 200 日线但未突破)
  基本面: 85 (上游报价继续走强)
  情绪: 75 (北向日买入 3.2 亿，中等强度)

核心故事跟踪:
  ✓ 钛材报价 +2.3% → 支持“产业链景气”假设
  ✓ 航发订单预告未更新 → 暂无证伪信号
  ⚠ 北向近 3 日总买入 12 亿，弱于上周 → 情绪冷却

结构化判断:
  ⏳ 未进场: 技术面未突破确认，当前评分不够强
  📍 已持仓: 核心故事未失效，继续监控订单预告与北向
```

## 6. 分阶段计划

### 阶段 0 — 地基（0.5 天）
- uv 项目骨架、`.env` 模板、SQLite schema、`cli.py` 入口
- **验收**：`uv run python -m src.cli --version` 跑通

### 阶段 1 — 产业链图谱引擎 ⭐（2–3 天，最核心）
- `universe.py`：akshare 拉全市场代码表缓存到 SQLite + 名称模糊匹配
- `expander.py`：Claude API 输入主题 → 分层产业链 JSON（总装→分系统→上游材料）
- `resolver.py`：公司名校验映射到真实代码（防幻觉）
- `quotes.py`：给每个节点挂市值 + 近期表现
- **验收**：`cli theme "中国军工"` 输出带价格的分层产业链表

### 阶段 2 — 入场框架引擎 ⭐（2 天）
- `entry.py`：技术/基本面/情绪三维打分
- `thesis.py`：记录每个持仓“为什么进”
- `frameworks.yaml`：框架定义持久化
- **验收**：能为某概念算出当日入场评分（如“军工今天 78 分”）

### 阶段 3 — 故事监控层 ⭐（2 天）
- `thesis_validator.py`：持续监控进场假设是否成立
- 每个假设映射到可观测指标（订单/库存/北向/财报）
- `flows.py`：北向资金、板块轮动
- **验收**：假设被证伪时系统明确给红灯

### 阶段 4 — 真实持仓接入（1–2 天）
- FutuOpenD 网关常驻配置 + `futu_client.py`（港股/美股持仓+实时）
- `ibkr_client.py`（美股/中概持仓，只读）
- **验收**：打印真实组合 + 当日盈亏

### 阶段 5 — 决策建议生成（1.5 天）
- `advisor.py`：综合入场评分 + 故事监控状态 → 结构化判断
- `exit.py`：基于故事失效的出场信号
- **验收**：对每个关注概念输出“入场评分 X/100，核心故事 Y/Z 维度绿灯”

### 阶段 6 — 直觉迭代层（2 天）
- `judgment.py`：模糊判断 → 可证伪子命题 → 标注验证数据 + 当前支持/证伪
- Notion 观点库沉淀
- **验收**：输入“军工今年订单会前置”，输出 3–5 条带数据缺口的子命题

### 阶段 7 — 日报 + 调度（1 天）
- `daily.py`：汇总评分变化 + 故事验证进展 + 结构化判断 → Markdown → Notion
- `launchd` 每天收盘后跑（A股 15:00 / 美股考虑时差），休眠补跑
- **验收**：连续 3 天自动出报告

## 7. 已知坑

- **FutuOpenD 必须后台常驻**，Mac 重启/休眠后要能自动拉起 → 阶段 4 单独处理。
- **akshare 接口偶尔变更或限频** → quotes 层做缓存 + 重试 + 降级。
- **LLM 产业链展开必须固定 JSON schema** 输出，否则 resolver 无法稳定解析。
- **跨市场时区**：A股/港股/美股收盘时间不同，调度要分市场触发。
